Reading Order: LLM Inference and Infrastructure Learning Path

Which part of which guide to read next, where each video fits, and when you're done with each stage.

Read the three guides in this order: Project 1 (one GPU) first, then the SR-IOV deep dive's Linux half, then Project 2 (multi-node), dipping into the SR-IOV guide's Kubernetes half right before you touch a cluster. Watch each video at the point it's listed, not before.

The path at a glance

The three guides: Project 1: Inference Benchmark Lab (P1), SR-IOV on Linux and Kubernetes (SR), and Project 2: Disaggregated Serving over RDMA (P2). P1 and P2 also live as WALKTHROUGH.html in ~/code/inference-bench-lab and ~/code/disagg-rdma-lab.

Times assume evenings and weekends. Stages 6–8 need no GPUs, so you can do them while you wait for cluster access.

Stage by stage

Work down this list in order. Each item is one sitting.

Stage 1: How inference works

  1. Optional warm-up: How LLM Inference Actually Scales (≈35 min), the whole story in one sitting.
  2. P1, How to use this guide: the restaurant picture and the glossary.
  3. P1, Part 1.1–1.3 (two phases, KV cache, batching), with NVIDIA's Mastering LLM Techniques: Inference Optimization (KV cache through PagedAttention) open beside it.
  4. Watch How does an LLM server handle millions of requests at the same time? (≈41 min) in full.
  5. P1, Part 1.4–1.7 (parallelism, quantization, speculative decoding, metrics and SLOs), then Check yourself before moving on. Compare with Part 7, the answer key.

Stage 2: The tools, on your laptop

  1. P1, Part 2 (tour of the repo), with the code open.
  2. P1, Steps 1–3: install, predict, smoke test on the mock server.
  3. P1, Part 4 (reading the results) using your own mock charts.
  4. The GuideLLM cross-check from Step 3: a second benchmark tool should agree with the first.

Stage 3: Inside a real engine

  1. The Annotated LLM Server: how vLLM is organised.
  2. tinyserve, the first ≈75 minutes, coding along: paged KV cache, prefix caching, continuous batching, chunked prefill.

  4. SR, Part 5 (Lab A): do Part 4 for real in the QEMU VM, plus Soft-RoCE.

  1. SR, Part 6: the building blocks and the 9-step pod start-up diagram.
  2. SR, Part 7 (Lab B): wire it up by hand in the VM, including 7.6 Break it on purpose.

Stage 8: Disaggregation, on your laptop

  1. P2, Part 2 (disaggregation concepts), then the Mooncake docs overview and, if you like papers, its FAST '25 paper.

Stage 9: The cluster lab

  2. P2, Steps 2–5: hardware checks, operators, measuring the wire. Keep SR, Part 11 (troubleshooting) open.

  4. Before Step 11: the llm-d well-lit paths. Then Step 11.
  5. Before Step 12: the LWS README and the vLLM LWS page. Then Step 12.

  7. SR, Part 10 (security and day-2) once you've seen a policy drain a node.
  8. P2, Step 16 (write it up) and P2, Part 6 again with real numbers.

Stage 10: Interview-ready

Rotate through P1 Part 6, P2 Part 7 and SR Part 12, out loud. For each answer, check you said the mechanism, a number you measured, the trade-off, and how you measured it.

Rules that make it stick

  • Predict before every run. Write the number you expect, then explain the gap. This is the habit interviewers and clients notice.
  • Don't skip the laptop stages. Stages 2, 6, 7 and 8 cost nothing and make the GPU and cluster weeks several times faster.
  • One finding sentence per experiment: on [hardware], for [workload] at [SLO], changing [X] moved capacity from A to B, because [mechanism]. If you can't write because, go back a stage.
  • Pass every Check line before moving on. If one fails, that's the lesson, not a detour.
  • Stop collecting resources once you're running experiments. Doing teaches more than more watching; the videos are listed exactly where they pay off.
  • Explain it out loud weekly, in the interview shape: mechanism, number, trade-off, how you measured it.
